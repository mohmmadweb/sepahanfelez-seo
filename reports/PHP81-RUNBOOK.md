### الف. چرا deprecation ها مشکلی ایجاد نمی‌کنند

PHP 8.1 برای «پاس دادن null به پارامتر رشته‌ای» هشدار deprecation می‌دهد و این
در یک کدبیس لاراول ۸ زیاد اتفاق می‌افتد. اما لاراول این‌ها را به کانال لاگ
`deprecations` می‌فرستد، و `config/logging.php` این کانال را تعریف نکرده است.
در آن حالت `HandleExceptions::ensureDeprecationLoggerIsConfigured()` درایور
`null` را می‌گذارد — یعنی **دور ریخته می‌شوند**. نه لاگ باد می‌کند، نه چیزی روی
صفحه چاپ می‌شود. این را لازم نیست از قبل درست کنید.

### ب. قوی‌ترین شاهد: اجرای درخواست‌های واقعی زیر هر دو نسخه

قبول شدن `phpunit` زیر ۸.۱ به‌تنهایی تقریباً هیچ نمی‌گوید:
`HandleExceptions::handleDeprecation()` وقتی `runningUnitTests()` باشد بلافاصله
`return` می‌کند، پس آن ۳۴ تست ساختاراً نسبت به تنها چیزی که ۸.۱ عوض می‌کند کور
هستند. در پروداکشن هم (به دلیل درست §الف) نامرئی‌اند. یعنی هیچ‌جا این سؤال
پرسیده نمی‌شد.

`tests/php81-deprecation-probe.php` (در مخزن Ahanamn، commit `348fd360`) اپ
واقعی را روی یک دیتابیس sqlite مهاجرت‌شده بالا می‌آورد، بعد از bootstrap
error handler را از لاراول پس می‌گیرد، و ۱۲ درخواست واقعی dispatch می‌کند و هر
diagnostic را **ثبت** می‌کند به‌جای دور ریختن. روی ۷.۴ هم اجرا می‌شود — نکته
دقیقاً همین است.

`tests/probe-diff.py` دو اجرا را مقایسه می‌کند. اول باید نرمال‌سازی کند: PHP 8.0
یک خانواده از diagnostic ها را بدون تغییر معنا تغییر نام داد — خواندن پراپرتی
تعریف‌نشده روی ۷.۴ `NOTICE: Trying to get property 'x' of non-object` است و روی
۸.۱ `WARNING: Attempt to read property "x" on null`. بدون نرمال‌سازی، هر ۲۲ مورد
هم‌زمان «جدید» و «حذف‌شده» گزارش می‌شوند و سیگنال گم می‌شود.

نتیجه، با همان داده و همان مسیرها روی هر دو نسخه:

```
7.4.33   ۲۲ diagnostic متمایز
8.1.34   ۲۲ diagnostic متمایز
deprecation های ایجادشده روی ۸.۱ :  ۰
موجود روی ۸.۱ ولی نه روی ۷.۴     :  ۰
هر ۱۲ مسیر: کد وضعیت یکسان
```

یک‌به‌یک، همان فایل، همان خط، همان تعداد. **تغییر نسخه هیچ چیز جدیدی تولید
نمی‌کند.**

بازتولید:

```bash
cd /home/mlops/mohammad/ahanamn-src
# doctrine/dbal برای migrate روی sqlite لازم است و در vendor پروژه نیست؛
# جدا نصبش کنید و به composer.json پروژه دست نزنید.
for V in 7.4 8.1; do
  docker run --rm --user $(id -u):$(id -g) -v "$PWD":/app -v /path/to/dbal-$V:/dbal:ro \

done
python3 tests/probe-diff.py /tmp/probe-7.4.json /tmp/probe-8.1.json
```

## تنها ریسک واقعیِ باقی‌مانده: افزونه‌های PHP

در cPanel فهرست افزونه‌های فعال **برای هر نسخهٔ PHP جداگانه** نگهداری می‌شود.
سوییچ ۷.۴ → ۸.۱ فهرست را منتقل **نمی‌کند**. اگر یکی از این‌ها زیر ۸.۱ خاموش
باشد، سایت با کد کاملاً سالم می‌شکند:

| افزونه | اگر نباشد چه می‌شکند |
|---|---|
| `pdo_mysql`, `mysqlnd` | **همه چیز** — اتصال دیتابیس |
| `mbstring` | متن فارسی، جست‌وجو، برش عنوان‌ها |
| `openssl` | `APP_KEY`، سشن، HTTPS خروجی، درگاه پرداخت |
| `json`, `pcre`, `ctype`, `tokenizer` | بوت لاراول |
| `fileinfo` | اعتبارسنجی آپلود در پنل ادمین |
| `xml`, `dom`, `simplexml`, `libxml`, `xmlreader`, `xmlwriter` | `sitemap.xml` |
| `zip`, `zlib` | **ورود اکسل قیمت‌ها** (`maatwebsite/excel`) |
| `gd` | آپلود و تغییر اندازهٔ تصاویر (`intervention/image`) |
| `curl` | فراخوانی درگاه پرداخت و پنل پیامک (`guzzle`) |
| `iconv` | تبدیل انکودینگ |
| `bcmath` | محاسبات مبلغ در درگاه |

**پیش از زدن دکمهٔ سوییچ**، در cPanel → _Select PHP Version_ نسخه را روی ۸.۱
بگذارید و فقط تب **Extensions** را ببینید و با فهرست ۷.۴ مقایسه کنید. اگر
هرکدام از بالا تیک ندارد، اول تیک بزنید.

### گام ۵ — پنج مسیری که هیچ تستی پوشش نمی‌دهد

تست‌ها این‌ها را لمس نمی‌کنند و تغییرات رفتاری PHP 8 دقیقاً همین‌جا بیرون می‌زند.
**دستی راه بروید:**

1. **سبد خرید** — افزودن کالا، تغییر تعداد، حذف، اعمال کد تخفیف
2. **ثبت سفارش** — یک سفارش واقعی تا مرحلهٔ قبل از پرداخت
3. **درگاه پرداخت** — یک تراکنش با کمترین مبلغ ممکن، تا برگشت به سایت
4. **ورود اکسل قیمت‌ها** — یک فایل واقعی (این `ext-zip` را می‌آزماید)
5. **پنل ادمین** — ورود، ویرایش یک محصول، **آپلود یک تصویر** (این `ext-gd` را
   می‌آزماید)، ذخیرهٔ یک اسلاید

## آنچه بعد از موفقیت هم **نباید** انجام دهید

- `composer.json` را روی `"php": "8.1.*"` نبرید.
- `"platform": {"php": "7.4.33"}` را عوض نکنید.
- `PHP_VERSION: "7.4"` را در `.github/workflows/deploy.yml` عوض نکنید.

هیچ‌کدام سودی ندارند و هر سه راه برگشت آنی را می‌بندند. تنها دلیل موجه برای
دست زدن به آن‌ها این است که بخواهید پکیجی نصب کنید که PHP 8 لازم دارد — که
الان چنین چیزی در کار نیست.
