۴موج ۲ — نجات تجربه‌ی موبایل

۴.۱ بازسازی مقیاس تایپوگرافی — مهم‌ترین تغییر کل کار

ریشه‌ی مشکل این بود که یک عدد دو کار بی‌ربط را همزمان انجام می‌داد:

/* قبل */
@media (max-width: 375px) { html { font-size: 6px } }   /* برای کوچک کردن چیدمان */
body { font-size: 1.4rem }                              /* = 8.4px  ← ناخواسته */

راه‌حل، جدا کردن این دو کار از هم بود، نه بزرگ کردن ریشه (که چیدمان را می‌ترکاند):

/* بعد */
@media (max-width: 375px) { html { font-size: 50% } }   /* چیدمان: ۸px، و درصد ⇒ تنظیم فونت مرورگر کار می‌کند */
:root { --type-unit: 1.4286rem }                        /* = 11.43px در همان breakpoint */
body { font-size: calc(1.4 * var(--type-unit)) }        /* = 16px، در هر عرض صفحه */

مقدار --type-unit در هر breakpoint طوری تعریف شده که همیشه به همان ۱۱.۴۳ پیکسل برسد. یعنی متن دیگر با مقیاس چیدمان کوچک نمی‌شود، ولی چون بر حسب rem است، هنوز از تنظیم «اندازه‌ی فونت» مرورگر کاربر پیروی می‌کند.

دو تصمیم که عمداً گرفته شد
۱) فقط اندازه‌های زیر 2rem تبدیل شدند (۶۹ مورد). بالاتر از آن تیتر و آیکون است و باید با چیدمان کوچک شود — یک عدد ۵rem که روی دسکتاپ می‌ماند، روی موبایل جا نمی‌شود.
۲) ریشه‌ی موبایل از ۶ به ۸ پیکسل رفت (نه بیشتر). این ۳۳٪ بزرگ‌تر شدن، همه‌ی paddingهای rem-based — و در نتیجه همه‌ی هدف‌های لمسی — را هم بزرگ می‌کند، بدون اینکه چیدمان را به هم بریزد.

۴.۲ جدول قیمت روی موبایل

زیر ۷۶۸ پیکسل هر ردیف جدول به یک کارت تبدیل می‌شود: نام محصول تیتر، قیمت درشت، نوسان به‌صورت درصد رنگی، و دکمه‌ی «افزودن به سبد» تمام‌عرض با ارتفاع ۴۴ پیکسل. برچسب هر مقدار از صفت data-label همان سلول می‌آید، پس نشانه‌گذاری همچنان یک جدول واحد است و رندر دسکتاپ دست‌نخورده می‌ماند.

ساختار جدول هم بازنویسی شد:

  • colspanها حذف شدند. 1/6/3/3/3/3/4 چیزی را ادغام نمی‌کرد؛ یک شبکه‌ی ۷ ستونی را داخل جدولی ۲۶ ستونی می‌ساخت، که یعنی هیچ سلول داده‌ای به سرستون خودش وصل نبود.
  • scope="col" روی هر ۷ سرستون و یک <caption> برای کل جدول.
  • id="h-c-ignore" تکراری به کلاس تبدیل شد. این id روی هر ردیف تکرار شده بود، و print-js با getElementById فقط اولی را پیدا می‌کرد — یعنی حذف ستون‌ها هنگام چاپ از ردیف دوم به بعد اصلاً کار نمی‌کرد.
  • دکمه‌ی خرید نام دسترس‌پذیر گرفت (aria-label) — ۲۴ دکمه در صفحه‌ی قیمت بدون نام بودند.

■ یک regex، ۴۹ قالب خراب

برای اضافه کردن loading="lazy" به تصاویر، از الگوی به‌ظاهر بدیهی <img[^>]*> استفاده کردم. اما در Blade، src="{{$slide->image()}}" یک > داخل عملگر فلش دارد — پس تطبیق وسط attribute تمام می‌شد و صفت‌ها را داخل عبارت PHP تزریق می‌کرد. 

src="{{$slide- loading="lazy" decoding="async">image()}}"

چطور پیدا شد: همان تست موجود مخزن که هر ۱۳۰ قالب Blade را کامپایل می‌کند، فوراً شکست خورد. ۴۹ تگ در ۳۱ فایل ترمیم شد و یک اسکنر واقعی نوشتم که {{ }} و کوتیشن را دنبال می‌کند. همان اسکنر حالا داخل بررسی ایستا هم هست.

■ thead مخفی که ۶۱۰ پیکسل عرض گرفت

برای مخفی کردن سرستون‌ها در حالت کارت، از تکنیک استاندارد «visually hidden» (position:absolute; clip:rect(0 0 0 0)) استفاده کردم. روی <thead> این کار نمی‌کند: ردیف همچنان به عرض طبیعی طولانی‌ترین سرستون چیده می‌شد و عرض سند را در ویوپورت ۳۷۵ به ۶۱۰ پیکسل رساند. چطور پیدا شد: اندازه‌گیری scrollWidth قبل و بعد. راه‌حل display: none بود — که چیزی از دست نمی‌دهد، چون در حالت کارت هر سلول برچسب خودش را به‌صورت متن دیدنی چاپ می‌کند.

■ هدف لمسی ۴۴ پیکسلی که صفحه‌بندی را شکست

بزرگ کردن لینک‌های صفحه‌بندی به ۴۴ پیکسل درست بود، ولی نصف کار: صفحه‌ی /price ده‌ها صفحه دارد و ده لینک ۴۴ پیکسلی روی یک ردیف بدون wrap می‌شود ۵۲۰ پیکسل. چطور پیدا شد: یک اسکریپت که تک‌تک ۷۴۳ عنصر صفحه را مخفی می‌کرد و scrollWidth را دوباره می‌خواند تا مقصر را پیدا کند. راه‌حل: flex-wrap و کوچک کردن chevronهای ۶rem‌ی.

۱۰قدم بعدی — و یک تصمیم با شماست

⚠ کد منتشر نشده است
همه‌ی این تغییرات در مخزن محلی /home/mlops/mohammad/ahanamn-src است و هنوز commit یا push نشده. در این پروژه، push روی شاخه‌ی main به‌طور خودکار روی سایت زنده مستقر می‌شود — یعنی push کردن، منتشر کردن است. انتشار یک تصمیم غیرقابل‌بازگشتِ روبه‌بیرون است و بدون تایید شما انجام نشد.

وقتی آماده‌ی انتشار بودید

  1. قبل از هر چیز، فایل SQL ایندکس‌ها را در phpMyAdmin اجرا کنید. بی‌خطر است و می‌تواند قبل یا بعد از استقرار انجام شود، ولی هرچه زودتر بهتر — بیشترین بهبود کارایی به‌ازای کمترین کار.
  2. بعد از استقرار، با پروفایل تمیز مرورگر بررسی کنید. سرور فایل‌های استاتیک را یک هفته کش می‌کند. (نام فایل‌ها cache-bust دارند، ولی این عادت را نگه دارید.)

  4. یک بار وارد پنل شوید و جستجوی منو و لوگوی جدید سایدبار را ببینید.
  5. یک برگه‌ی قیمت چاپ بگیرید — لوگو و شماره تماسش الان درست است.
