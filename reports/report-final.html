۳سه رگرسیونی که ساختم

مالک سایت هر سه را قبل از من دید. این بخش مهم‌تر از بقیه‌ی گزارش است.

■ منوی موبایل نامرئی باز می‌شد

به #sideMenu وقتی بسته است visibility: hidden دادم و برگرداندنش را به کلاسی سپردم که sidemenu.js اضافه می‌کند. آن کلاس هرگز به سرور نرسید: webpack.mix.js اصلاً این فایل را build نمی‌کند — یک کپی دستی است، و باید باشد، چون هدر openNav() را از onclick درون‌خطی صدا می‌زند و webpack آن تابع را scope می‌کرد. CSS رفت، JS نرفت.

و بدترین بخشش: آن قانون دنبال عددی بود که کاربر نمی‌بیند (scrollWidth)، و سرریز واقعی هم مال ردیف صفحه‌بندی بود. ناوبری سالم را برای بهتر کردن یک عدد نامرئی شکستم.

■ همبرگر روی دسکتاپ

بلوک هدف‌های لمسی، .navbar-toggler را کنار .cart و .user گذاشته بود و به همه‌شان display: inline-flex داد. آن بلوک scope ندارد و آخر import می‌شود، پس @media (min-width:993px){ display:none } را شکست داد. تغییر اندازه نباید قابلیت دیده شدن را عوض کند.

■ هدر موبایل ۲۶۲ پیکسل

position: static لوگو را از موقعیت‌دهی absolute دسکتاپ بیرون آورد و چون آن anchor اولین فرزند <header> است، بالای نوار قرمز چید. و height: 4.4rem به .logo.big-logo باخت (دو کلاس از یکی قوی‌تر است) → ۲۰۰ پیکسل رندر شد.

درس مشترک
هر سه با باز کردن سایت در ۳۷۵ پیکسل و نگاه کردن پیدا می‌شد. من اندازه‌ی فونت، جعبه‌ی هدف لمسی و عرض اسکرول را سنجیدم و هیچ‌وقت به خود هدر نگاه نکردم. اندازه‌گیری جای نگاه کردن را نمی‌گیرد.

درباره‌ی خط لوله‌ی استقرار
استقرارها بین ۱۷ تا بیش از ۵۰ دقیقه طول کشیدند و یک بار کاملاً متوقف ماند تا دستی اجرا شد. دلیل محتملش در خودِ HANDOFF نوشته شده: cPanel API بعد از چند هزار درخواست نرخ را محدود می‌کند و به‌جای JSON یک صفحه‌ی HTML برمی‌گرداند. اگر آپلودکننده به آن بخورد، job معلق می‌ماند و چون cancel-in-progress: false است، هر push بعدی پشتش صف می‌کشد.

اگر استقراری بیش از ۲۰ دقیقه طول کشید: تب Actions → اجرای معلق را Cancel کنید → بعد Run workflow. و درخواست SSH از 7hostir همچنان بزرگ‌ترین ساده‌سازی ممکن برای این پروژه است.
