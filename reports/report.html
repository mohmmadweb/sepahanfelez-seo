۱خلاصه اجرایی و کارنامه

سپاهان فلز یک سایت B2B فروش مفتول و توری فولادی است که هسته‌ی ارزش آن «جدول قیمت لحظه‌ای» است. معماری کلی سالم و حرفه‌ای است: لایه‌بندی درست Laravel، سیستم نقش و دسترسی واقعی، خط لوله‌ی CI/CD خودکار، و یک هویت بصری منسجم روی دسکتاپ. روی دسکتاپ سایت خوب کار می‌کند.

اما سه مشکل ساختاری، ارزش این پایه‌ی خوب را می‌بلعند: (۱) تجربه‌ی موبایل عملاً شکسته است — اندازه‌ی متن پایه روی موبایل ۸.۴ پیکسل است و جدول قیمت (یعنی خودِ محصول) در ویوپورت موبایل جا نمی‌شود؛ (۲) پشته‌ی اجرایی از پشتیبانی خارج شده — PHP 7.4 و Laravel 8 هر دو از سال ۲۰۲۲/۲۰۲۳ دیگر وصله‌ی امنیتی نمی‌گیرند؛ (۳) چند باگ کوچک اما پرتکرار در بک‌اند و جاوااسکریپت باعث شده کش‌ها هیچ‌وقت کار نکنند و یک خطا هر ثانیه روی تمام صفحات پرتاب شود.

۴تحلیل رابط و تجربه کاربری

۴.۱ نقاط قوت

  1. هویت بصری منسجم روی دسکتاپ. پالت چهاررنگی محدود و منضبط (#b42332 قرمز برند، #283264 سرمه‌ای، #495f9e آبی، #f7f7f7 خاکستری) که در تمام صفحات یکسان به‌کار رفته است. این نظم رنگی در پروژه‌های این مقیاس کم‌پیدا است.
  2. ست آیکون یکدست برای ۱۴ دسته محصول. همه خط‌نقاشی (line-art) با ضخامت یکسان داخل کادر قرمز. اصل «یک زبان آیکونی» رعایت شده — نه ایموجی، نه مخلوط filled/outline.
  3. نوسان قیمت فقط با رنگ منتقل نمی‌شود. کنار درصد سبز/قرمز، آیکون مثلث بالا/پایین هم هست. این دقیقاً قاعده‌ی color-not-only در WCAG است و اغلب سایت‌های مالی آن را نقض می‌کنند.
  4. جدول قیمت دسکتاپ واقعاً خوب است. هفت ستون معنادار (نام، قیمت لحظه‌ای، نوسان، نمودار، آخرین تغییر، خرید) با اسپارک‌لاین درون‌خطی و مودال نمودار تفصیلی برای هر محصول.
  5. «چاپ گزارش» با استایل‌شیت اختصاصی. فایل print.scss جداگانه و print.js — یک نیاز واقعی B2B که معمولاً فراموش می‌شود.
  6. RTL درست پیاده شده. dir="rtl"، lang="fa"، Bootstrap 5 در حالت RTL بومی، اعداد فارسی، و فونت IRANSans با نسخه‌ی FaNum (ارقام فارسی داخل فونت).
  7. فیلتر مشخصات فنی روی صفحه‌ی دسته. کاربر می‌تواند بر اساس ضخامت مفتول، نوع گالوانیزه، ضخامت خار و... محصول را محدود کند — دقیقاً الگوی درست برای کالای صنعتی.
  8. breadcrumb به‌همراه JSON-LD. صفحات دسته هم مسیر بصری دارند هم BreadcrumbList و CollectionPage ساختاریافته.
  9. کانال ارتباط سریع. دکمه‌ی شناور واتس‌اپ و چت Goftino — برای فروش B2B مسیر تماس کوتاه است.
  10. منوی کشویی موبایل (sidemenu) با سلسله‌مراتب سه‌سطحی که ساختار دسته‌بندی عمیق را درست بازتاب می‌دهد.

■ جدول قیمت روی موبایل

کلاس .separated-table table در _variables.scss مقدار min-width: 992px دارد. در ویوپورت ۳۷۵ پیکسلی این یعنی جدول ۲.۶ برابر عرض صفحه است. اسکرین‌شات موبایل صفحه‌ی اصلی نشان می‌دهد کاربر فقط ستون «نام» و لبه‌ی یک ستون دیگر را می‌بیند — قیمت، درصد نوسان و دکمه‌ی خرید کلاً بیرون کادرند.

شمارش زنده: ۲۵۶ المان در صفحه‌ی /price و ۱۶۷ المان در صفحه‌ی اصلی، بیرون از مرز ویوپورت قرار دارند.

پیشنهاد: زیر ۷۶۸px جدول را به کارت تبدیل کنید — هر محصول یک کارت با نام (تیتر)، قیمت (بزرگ)، نوسان (چیپ رنگی+آیکون) و دکمه‌ی خرید. این الگوی استاندارد جدول‌های داده روی موبایل است و به‌جای اسکرول افقی، اسکرول عمودی طبیعی می‌دهد.

■ باگ‌های کش — کش عملاً کار نمی‌کند

باگ ۱ — کلید ناهمخوان در Redirecting:

    return cache()->get('redirections');

باگ ۲ — کلید اشتباه در HomeController:

if (cache()->has("home.all_prices")) { ... }   // هرگز true نمی‌شود
else {
    $all_prices = Price::query()->whereHas(...)->with(...)->take(10)->get();
    cache()->put("home.most_sales", $all_prices, $cacheTime);  // ← کلید اشتباه
}
if (cache()->has("home.most_sales")) {          // حالا true است، ولی مقدارش قیمت‌هاست
    $most_sales = cache()->get("home.most_sales");   // ← داده‌ی نوع اشتباه

دو اثر: کوئری اصلی صفحه‌ی اصلی هیچ‌وقت کش نمی‌شود، و کش most_sales با داده‌ی نوع دیگری آلوده می‌شود. (خوشبختانه $most_sales در قالب استفاده نمی‌شود، پس فعلاً خطای قابل‌مشاهده‌ای تولید نمی‌کند — که خودش نکته‌ی بعدی است.)

باگ ۴ — کوئری مرده: متغیرهای $most_sales و $most_new پرس‌وجو و به قالب ارسال می‌شوند، اما در home.blade.php هیچ استفاده‌ای ندارند (بخش مربوطه کامنت شده است). دو کوئری اضافی در هر بارگذاری صفحه‌ی اصلی.
